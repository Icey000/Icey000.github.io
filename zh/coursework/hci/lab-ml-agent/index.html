作业要求什么，我选了什么#

HCI 讲义第 166 页要求“用 ML agent 做第一个较大的 Unity 应用”，并写过程博客。Roll-a-ball 只是“可以选”的例子之一，不是必须。ML 指机器学习；原文没有要求多智能体，也没有指定算法。

我不想做“小球学会碰方块”。这是人机交互课，所以把智能体设计成听人指挥：

车站停电。人告诉救援机器人要拿哪种电芯（蓝色或橙色）。机器人要找到它、不碰错的那颗、穿过会周期性放电的电缆区，把电芯送到发电机。

“要哪颗电芯”是策略网络的输入（目标条件智能体）。所以同一个训练好的网络，既可以由人按键指挥，也可以（见下文）直接听自然语言。

环境#

项目版本／数值

没有独显也够用：机器人靠数值和射线感知世界，不看摄像头画面，CPU 上每秒约 2000 步。

智能体设计#

它能看到什么（25 个数 + 136 个射线值）

  • 要求哪种电芯、自己手里拿着什么；
  • 两颗电芯和发电机相对自己的位置；
  • 自己的速度、是否被电晕；
  • 每条电缆的相对位置、方向、是否在放电、还有多久切换；
  • 360° 射线，能分辨墙、电芯、发电机、通电／断电的电缆。

它能做什么： 两个连续动作——左右、前后移动。

奖励设计

事件奖励
把指定电芯送到发电机+1.0（本局结束）
第一次拿到指定电芯+0.2
碰到错误电芯（被拒绝，不会拿起）−0.2（每局一次）
被放电电缆电到（掉落电芯，僵住 1.5 秒）−1.0
离当前目标更近每米 +0.1
时间40 秒内总共 −0.5

课程式训练（curriculum）： 第一课没有电缆；平均奖励过线后，第二课加一条电缆，第三课再加一条。

过程：四次尝试，三个真正的问题#

工具链问题（几分钟解决，但值得记下来）#

  1. 批处理模式报“No valid Unity Editor license found”。 许可证客户端需要 Unity Hub 提供的登录令牌，当时 Hub 没开；启动 Hub 后正常。
  2. ModuleNotFoundError: pkg_resources。 mlagents 1.1.0 仍依赖 pkg_resources，新版 setuptools 已删掉它；装 setuptools<70 解决。
  3. The option ﻿behaviors … is invalid。 PowerShell 的 Set-Content -Encoding utf8 在 YAML 开头写了 BOM；改成无 BOM 的 UTF-8 解决。

v1：成功率卡在 8%#

训练 40 万步后只有约 8% 的局成功。统计显示装错和装对一样多：机器人一旦拿错电芯就放不下，后面整局都是死路，什么也学不到。修正： 碰到错的电芯直接拒绝并扣分；“靠近目标”的奖励加强为原来 5 倍。

v2：成功率 97%，却根本没学会躲电缆#

v2 学得很快。随后我把导出的模型跑 200 局，和一个写死规则的对照控制器（直线冲向目标，不管电缆）比较：

v2 评估（2 条电缆）成功率平均用时每局触电
训练出的 PPO（v2）97.5%6.0 秒1.00 次
写死规则直线冲99.5%4.0 秒1.13 次

学出来的策略和完全不管电缆的控制器触电一样多。原因：触电只扣 0.3 分、僵 1 秒，硬闯比绕路划算；而且机器人根本不知道电缆什么时候通电。没有这个对照，我只会写“成功率 97%”，完全发现不了问题。

修正（v3）： 触电扣 1.0 分、僵住 1.5 秒；把每条电缆的位置、方向、通电状态、切换倒计时加入观察。

v3：学会躲开放电电缆#

曲线能看出课程训练的过程：第一条电缆出现时（104 万步），触电一度飙到每局约 6 次、成功率下跌，之后机器人学会安全穿过。400 万步共训练 36 分钟。

在程序里评估，v3 触电远少于对照（每局 0.42 次 vs 1.51 次），但成功率只有 92%：8% 的局在电缆旁犹豫到超时。它在“两条电缆”的完整任务上只练了 240 万步。

v3 微调：最终模型#

从 v3 的权重继续，只在两条电缆的完整任务上再训练 200 万步，学习率降到 1.5e-4，探索程度降低（熵系数 3e-3）。用时 18 分钟，大部分超时消失了。

结果#

评估是在 Windows 程序里运行导出的 ONNX 模型（不是训练时的统计），随机 300 种布局，两条电缆都在。

策略成功率成功时平均用时每局触电碰到错电芯
训练出的 PPO（v3 微调，最终版）97.3%6.2 秒0.33 次12.7%
训练出的 PPO（v3）92.0%7.4 秒0.42 次12.7%
写死规则直线冲97.3%4.3 秒1.51 次3.3%

最终的学习型机器人成功率与写死规则持平，触电次数少 78%。 代价是慢约 2 秒：等电缆断电再过需要时间。它碰到错误电芯也更多（12.7%），因为奖励只教它躲电缆，没有教它远离另一颗电芯。

实际游玩：人来下指令#

游玩版中，人随时按 1（蓝）或 2（橙）。如果手里的电芯不再符合指令，机器人会放下并立刻改道——同一个训练好的网络，现在接受人的指挥。

触电：僵住 1.5 秒。中途改成橙色：机器人重新规划路线。

送达：发电机变绿，然后进入新的随机布局。（这张来自微调前的 v3 模型，其余截图都是最终模型。）

画面刻意用简单几何体加上 URP 辉光和应急灯光；精力主要放在学习问题本身。

直接对机器人说话：自然语言指令#

人指挥队友不会按数字键。我加了一层语言接口，完全在笔记本本地运行：本地大模型（Qwen2.5-3B，通过 Ollama 0.40.15，只用 CPU）读懂玩家输入的中文、英文或法文，再交给训练好的策略去执行。

最终设计：模型负责读懂，程序负责落地#

模型不决定指的是哪颗电芯，只标注玩家怎么描述它：颜色、形状、closer_to_robot（离机器人近）、left、是否被否定，或者 unspecified（没说）。随后由程序用真实场景几何算出是哪颗；如果什么都没指明，就由程序追问“蓝色还是橙色？”。机器人每次都会用玩家的语言复述计划，误解在行动前就能被看到。

怎么走到这一步：三个版本，都有测量#

我写了一套 45 条带标准答案的指令（8 类、三种语言、两种场景布局），每个版本都在游戏程序里、走玩家实际使用的同一条代码路径来评估。对照组是关键词规则解析器（三种语言的颜色、形状同义词）。

版本准确率（45 条）空间否定追问闲聊平均延迟
关键词规则57.8%0/80/54/40/3< 0.01 秒
大模型直接选电芯（提示词 v1）77.8%5/85/50/40/33.9 秒
+ 程序预先算好关系、规则更严格（v2）82.2%6/85/50/43/34.1 秒
模型解析、程序落地（最终版）91.1%8/85/52/43/35.3 秒

每一步学到的：

  • v1： 3B 模型处理否定和顺序都不错，但从不追问——让它“拿电池”，它直接猜蓝色；还会用中文回答英文，因为照抄了我写的中文示例。
  • v2： 我在程序里算好“离机器人近的是橙色”并写进提示词。闲聊和回复语言修好了，但模型仍然有时和给它的关系相矛盾，也还是不追问。继续改提示词，没法让 3B 模型在这件事上可靠。
  • 最终版： 把“决定是哪颗”从模型里拿出来。空间指代变成 8/8，因为几何现在是算出来的，不是猜出来的。

因为我是对着这 45 条调的，所以之后又写了 20 条全新的保留测试句（新说法、新布局），只评估一次：最终版 85%，关键词规则 55%。 剩下的错误正是上面的弱点：对“拿个电池过来”，模型把两颗都列出来，而不是标成 unspecified。

实际试玩中的真实观察#

  • 每条指令 4–7 秒（CPU，同时在渲染游戏）。对“去做这件事”的指令可以接受，不适合实时操控；原来的 1 / 2 键仍然即时生效。
  • 有一次试玩中，策略卡在电缆旁反复触电，直到我换布局——这正是它 2.7% 超时率背后的同一个失败。语言层再好，也受限于下面的策略。
  • 让系统可靠的是“程序落地”。语言模型擅长读懂，不该让它负责测量。

一起玩：人机协作#

下指令只是和机器人合作的一种方式。在协作版里，人也下场。下面先是第一版的玩法，后文还有改版：

  • 发电机现在需要两颗电芯都装上，所以必须分工；
  • 玩家用 WASD 控制一个角色，规则和机器人一样（拿起、安装、会被电晕）；
  • 场边有一块断电踏板：有人站在上面时，所有电缆停止放电——机器人看到电缆断电，就能安全穿过。

训练好的策略没有改变，变的是由谁决定机器人去拿哪颗。我做了三种队友：

队友怎么决定
固定分工永远先拿蓝色；只有自己的电芯被拿走后才改。
自适应根据玩家的移动推断玩家要拿哪颗，自己拿另一颗。每 0.1 秒，朝某颗电芯靠近会提高它的概率；旧证据会衰减，所以玩家改主意也能跟上。这个判断显示在屏幕上（“Robot’s guess of your goal”）。
语言指令等玩家通过上面的本地大模型层打字下指令。

第一轮测试：模拟搭档（不是真人）#

在找人之前，先用一个写好规则的“替身”检验逻辑：它多数时候去拿离自己近的那颗，有时拿另一颗，20% 的回合会在开头改主意，走路会左右摆动，遇到通电的电缆会停下等待。下面是按后文“试玩发现的问题”修复之后重新跑的结果，每种队友各 150 回合：

各 150 回合固定分工自适应
机器人和搭档去拿同一颗的回合48.0%（95% 置信区间 40–56）3.3%（0.7–6.7）
恢复供电的平均用时（完成的回合）6.26 秒6.15 秒
60 秒内完成98.7%98.7%
目标推断准确率（对照搭档真实目标）—约 96%

推断搭档的目标，几乎消除了重复劳动。 0.11 秒的时间差不能下结论（自助法 95% 置信区间 −0.73 到 0.84 秒），所以我不声称自适应队友更快。修复前同样的测试是 44.0% → 0.7%；物理计时不完全确定，重复跑几次这些数字会差几个百分点。剩下的失败局，是模拟搭档拿着电芯一次次走进通电的电缆（一局触电 30 多次），这暴露的是我写的替身的缺陷，不是机器人的。而且模拟搭档检验的是我的代码，不是关于真人的证据。

第一次试玩发现的问题#

之后我自己玩了一遍（自由试玩，不属于任何测试）。马上发现两个问题，而 300 回合模拟一个都没发现：

  • 机器人有时会一直不动，直到时间耗尽。 我有 3 局都卡到 60 秒上限。机器人装好一颗之后，只要我离最后那颗更近，它就让给我去拿；即使我站在断电踏板上不动、正在帮它断电，它也一直干等。只剩一颗时，“你要去拿它”的概率永远约等于 100%，光看这个概率分不清“正在走过去”和“只是站在附近”。模拟搭档从来不会站着不动，所以模拟测试没测出来。现在改成：只有你真的在朝那颗走（停在电缆前等待有 1.5 秒宽限），机器人才让给你；你站上断电踏板，或者在去拿的路上被电了两次，它就立刻接手。
  • 触电不像惩罚。 我的角色只是突然停住，我不知道为什么。现在触电时会冒电弧、蓝色闪屏、发出电流声、镜头震动，被电晕的角色会闪烁，头顶出现“ZAP!”和眩晕倒计时条；电缆通电前 0.45 秒还会先闪烁预警。这些都只改画面，机器人的感知和游戏规则不变。另外，被电时掉落的电芯现在会落在电缆旁边，不会掉在电缆上让谁都拿不到。

试玩还让我意识到：这个游戏更像是和机器人赛跑，而不是合作。两边很少需要对方，断电踏板是唯一真正的相互依赖。让人和机器人真正需要彼此，比继续调参数更重要，所以接下来我改的就是这个。

改成真合作：被电网封住的发电机房#

新规则：发电机现在放在角落的一个房间里，四周被两条永远不会自己断电的电缆封住。只有站在断电开关（黄色踏板）上才能让电网断电：房间外一个，房间里一个。谁都没法独自把电芯送进去，两边必须轮流配合：一个人按住开关，另一个人通过；进了房间的人再从里面给对方开门。

  • 机器人会求助。 它拿着电芯走到电网前会停下，头顶气泡显示“Hold the breaker for me!”（帮我按住开关！），同时响一声提示音，你这一侧的开关上方闪烁“▼ STAND HERE”（站这里）。
  • 你也可以叫机器人帮忙。 按 E，或者输入“按住开关” / “hold the breaker”，机器人就走到它那一侧的开关上，一直站到你通过为止（“Breaker held — go!”）。这条指令用关键词规则处理，不经过语言模型，因为原来的“去拿哪颗电芯”的格式里没有这一项。
  • 三种队友的区别变成了“怎么帮忙”。 固定分工只在你开口时才去按开关。自适应除了推断你要拿哪颗，看到你拿着电芯走向电网时还会主动去按开关。它只在“能和你差不多同时到”时才提前出发，免得白白丢下自己的活。语言指令等你打字下令。
  • 游戏感： 90 秒备用电源倒计时、每局星级评分、局末统计“机器人给你开门几次 / 你给机器人开门几次”。碰到电网会被弹回自己那一侧。不弹回的话，站在一条永不断电的电缆上，眩晕一结束就会再被电一次，模拟里有一局被电了 50 多次。

让训练好的机器人学会配合，暴露了它学到的东西的边界。 每个修复都来自对失败局的逐帧记录：

出了什么问题原因修复
让它去按开关，它绕着开关转了一整局它训练时找的是电芯和发电机，射线传感器能“看见”它们；开关只是地上的一块区域，而且训练时只要走到目标 1 米左右就算完成去开关的路改用脚本（直线走，遇到房间拐角就绕开）
拿着电芯时，它停在离电网 4 米外徘徊，从不求助它学会的是“离通电电缆远一点，等它自己断电”，但这道电网永远不会自己断用脚本让它走到电网前，再停下求助
搭档打开电网后，它不往里走反而走开，两边一直互相等原因不明，策略从没遇到过这种情况穿过电网这一段也改用脚本，过去以后再交还给神经网络

所以训练出的神经网络仍然负责它学过的事：拿电芯、绕开电缆送到发电机。围绕电网的新技能是手写的。更干净的做法是带着搭档和电网重新训练一个策略；我把这一点写进局限，而不是藏起来。

这一次，会预判的队友确实更快：每局快 1.9 秒（自助法 95% 置信区间 1.7–2.1 秒），搭档在电网前少等 2.0 秒（置信区间 1.8–2.2 秒）。两种队友每局都要靠搭档开一次门，也给搭档开一次门，这正是这次改版的目的。不过这仍然是对着写好规则的替身测出来的；真人觉得好不好玩，要靠真人测试来回答，所以我在问卷里加了“和这个机器人一起玩很有意思”这一题。

真正的测试：已备好的真人测试工具包#

真正重要的是人怎么体验这几种队友——能不能预测它、信不信任它、屏幕上的“猜测”有没有帮助。我准备了一个在这台笔记本上运行的被试内实验：

  • 一键启动，输入被试编号；先练习一回合，再依次体验三种队友各 3 回合，顺序自动轮换（拉丁方）；
  • 每回合自动记录到 CSV（用时、是否完成、触电、机器人的目标被玩家抢走几次、改计划几次、打了几条指令、在电网前等了多久、双方各求助几次、各给对方开门几次）；
  • 每种队友一页问卷（是否按我想的做、可预测性、信任、团队感、是否碍事、脑力负担、好不好玩；偏好排序；“猜测”显示是否有用）；
  • 分析脚本按条件输出均值。3–6 名被试时，只做描述性报告，并配上被试的原话。

状态：还没有真人玩过。 做完测试后会把真实结果补在这里。

给后来者的建议#

  • 一定要和“笨办法”对照评估。 我最重要的发现（v2 不躲电缆）在训练曲线里完全看不出来。
  • 学习停滞时，找“死路状态”。 一个不可挽回的错误，会浪费大部分训练数据。
  • 给智能体做好决策所需的信息。 它感知不到的时机，就没法掐准。
  • 惩罚必须大于捷径的收益。 只要钻空子更划算，PPO 一定会找到。
  • 向量／射线观察不需要独显。 改为并行跑多个无画面进程。
  • 把 AI 的判断显示出来。 队友在猜你要做什么时，就把猜测放到屏幕上；这样令人意外的动作就变成可以解释的动作。
  • 找别人测之前，先自己玩。 我自己玩了十分钟，就发现了 300 回合模拟都没发现的卡死问题，因为我写的模拟搭档从来不会站着不动。
  • 小模型负责读懂，程序负责测量。 开始调提示词之前就留出保留测试句，否则只是在测自己对示例的拟合程度。

局限与下一步#

  • 每个策略只用一个随机种子、300 种布局评估；还没有用不同种子重复训练，所以数字代表一次训练，不是分布。
  • 语言测试规模小（45 + 20 条），而且是我自己写的；它们说明每次改动的方向，不是基准测试。
  • 人机协作的对比目前用的是模拟搭档。真人测试已准备好但还没做，所以不对“人怎么体验这三种队友”下任何结论。
  • 机器人的射线不会标记玩家，策略训练时身边也没有人，所以它不会主动给玩家让路。
  • 在封闭机房的协作版里，走到电网前、穿过电网、站上开关这几步是脚本控制的，因为训练好的策略做不稳。带着搭档、开关和常通电电网重新训练策略，是自然的下一步。

复现#

评估：TeamRescueDemo.exe -eval 300 eval.json（加 -baseline 为写死规则）。语言测试：TeamRescueDemo.exe -evalnlu nlu_tests.json out.json（加 -rules 为关键词对照）。游玩：先启动 ollama serve 并拉取 qwen2.5:3b，再运行 TeamRescueDemo.exe，输入指令按回车（1 / 2 / R 仍可用）。协作版：运行 TeamRescueCoop.exe（F1 / F2 / F3 切换队友，N 新回合）；模拟对比：TeamRescueCoop.exe -coopsim 150 out.csv -mode adaptive；真人测试：study\Run-Study.cmd。
